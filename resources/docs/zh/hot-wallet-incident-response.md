# 热钱包泄露应急与分层损失上限

## 威胁边界

币安于 2026-11-03 公布的 10 月 29 日事件初步调查指出，攻击者取得内部签名服务的未授权访问，并在正常提现流程之外发起交易；还利用 EIP-7702 在链上留下委托。暂停正常提现后，已在链上的委托和待确认交易仍能继续移动资产。报告称受影响资产约 63.4 亿美元，调查仍在进行。来源：[币安初步调查与响应](https://www.binance.com/en/square/post/384328127385979)。

因此，单纯更换热钱包地址或关闭 API 不构成止损。应假设 Wallet 应用、部署凭据或操作员终端可以被攻陷，让独立审批、三个原生 MPC 持有者和链上状态分别限制损失。

## 当前实现的安全基线

- 每个租户的链地址和 MPC key 按租户登记；备用热提钱包具有独立 key、地址及每资产目标/最高余额、单笔/24 小时提现上限。
- 新建热钱包仅处于 `STANDBY`。独立审批主机必须预装确切 key/地址的归集规则；预检逐资产核对地址、规则身份与指纹。链上库存由审批侧独立 RPC 观察、按原子单位缓存；EVM 观察复核同一高度的区块哈希并持久化高度与哈希，历史无锚点缓存须刷新。观察值不产生客户账本权益。Console 可在逐资产规则、余额和密钥核对后启用账户链备用钱包；暂停提现期间也可预先启用，新提现仍受暂停门控制。UTXO 和 XMR 暂不允许启用。
- 活跃钱包按优先级接收新账户链提现与归集。提现创建事务内固定原发送方并预留单笔、24 小时及库存额度；归集创建事务内固定目标，按观察余额、未核销的目标流入与单钱包最高余额计算剩余额度。提现暂停期间仍可向活跃安全钱包归集；旧钱包已隔离或退役且没有活跃替代钱包时，即使租户链被重新启用，提现和归集都拒绝回退旧默认地址。库存或容量不足时拒绝新任务。普通 EVM 单笔已确认提现可用独立审批侧的 finalized 区块、原交易、成功回执、目标/金额及同块余额证明逐笔释放库存本金占额；后台限量轮询未核销订单，Console 也可按原订单号核验。普通 EVM 直接归集同样须由独立审批侧证明原发送地址、原交易、最终成功回执和已包含该交易的目标余额，再在同一事务刷新库存并核销对应流入；后台限量轮询已确认但未核销记录，Console 可按原归集号重试。无法证明的交易保持占额；EIP-7702 批次和其他链归集仍继续保守占额。升级已有数据库时先执行 `scripts/ops/upgrade-hot-wallet-collection-accounting.sql`，再部署审批、Wallet 和 Console 新版本。
- 租户还需为每个链资产设置活跃热钱包总余额上限。启用备用钱包与创建新归集时，在同一租户链锁下锁住该资产的总限额，合计所有活跃热钱包的新鲜链上观察余额及已记录的流入，超额或任一活跃钱包观察失效即拒绝。迁移现有活跃钱包时，初始总上限等于其现行逐钱包上限之和；新增钱包前必须显式调高。降低上限可立即阻止新增归集，但不能使已有链上余额消失；外部直接向热地址转账也无法被本地限额阻挡。部署时先执行 `scripts/ops/upgrade-hot-wallet-aggregate-exposure.sql`，再更新钱包运行角色对此表的权限。
- 租户可暂停该链新提现，隔离热钱包时先在 Wallet 永久记录原事件并停止新授权，再向三个原生持有者和独立审批提交同一 key 禁用事件；确认失败会持久重试。恢复操作与紧急暂停使用同一数据库咨询锁串行化，并在锁内重新读取钱包状态。只要任何旧钱包的四方隔离回执尚未齐备，管理接口就拒绝恢复提现；已隔离或退役钱包存在而没有活跃替代钱包时也拒绝恢复。
- EIP-7702 的批量提现与归集签名均核对原资产权威 key，不能只检查中继 key。EVM 普通交易、既有误入账资产找回交易与 EIP-7702 批次在首次广播和未知交易重广播时，持租户链共享锁直到 RPC 返回，并复核原权威钱包状态；归集在提现暂停时还逐项核对原交易收款地址是否为当前安全活跃钱包。隔离后不能借已保存的中继签名重新发送，旧目标也不能借历史签名继续收到新广播。既有误入账资产找回流程受紧急暂停门限制，不能充当事件救援转账。已在链上可见的交易仍保留原批次继续对账。
- EIP-7702 批量提币账户投影现以 `tenant + chain + authority_address` 区分同链多个热钱包；原批次确认或回滚只更新其原地址，找不到原投影会回滚事务。既有数据库须先执行 `scripts/ops/upgrade-7702-multi-hot-payout-account.sql`，移除历史的单租户单链唯一约束；该迁移可重复执行。
- EIP-7702 批量提币领单先持租户链共享锁检查提现仍开放；它也可接受原订单已绑定的租户热提地址，但要在同一事务中复核钱包仍为活跃、地址与 MPC key 同租户同链同网络且一致、资产库存观察未失效且未超过 60 秒；隔离或备用地址不能进入新批次。旧 Gas 地址订单仍按原地址处理，不借领单阶段改写来源；后续签名和首次广播仍分别受独立授权与暂停/隔离门控制。
- Wallet 在申请新签名授权前和写入回执的数据库事务中复核热钱包库存失效标记。独立审批域对所有 EVM 新授权再独立读取实际发送方链上账户代码，确认空代码或已安装且代码哈希匹配的 EIP-7702 委托；同一签名槽的新会话重放也重新检查。此检查只是授权时的采样，不会撤回已签发证明、已广播交易或泄露私钥的链上权力。
- 提现订单固定最初链上来源地址。切换只可影响新订单，旧订单需取消、结算或逐笔对账。
- Console 应急切换按已提交阶段运行：在同一数据库事务中暂停该租户链提现并把旧钱包标为隔离，阻断新提现建单和向旧地址的新归集建单；随后将旧 key 在三名原生持有者和独立审批侧确认隔离，最后核验并启用备用钱包。隔离回执失败或备用钱包核验失败时保持暂停并可重试；成功返回仍明确 `assetTransferComplete=false`，不会自动恢复提现或迁移旧地址资产。尚未覆盖的链上原始广播路径需要逐链补门并对账。
- EVM、Aptos、Sui、Solana、NEAR、DOT、TON、TRON、XRP、ADA、HyperCore 的普通业务交易在链上未知时经广播门提交原签名；NEAR 代币注册、DOT/ADA Gas 补充和 XRP 地址准备交易也受提现暂停门控制。ADA 确认流程内的原交易重发同样经过广播门。出款复核租户暂停与原 key；归集持租户链共享锁到 RPC 返回，复核已持久化的原哈希、原 key 和暂停时的安全目标。已知链上交易只按原证据对账。尚需逐链核查其他辅助交易、未纳入上述入口的链和直接 RPC 发送路径。
- BTC 类 UTXO 的已签队列广播与 XMR 原生中继都先持租户链共享咨询锁再核对暂停状态；XMR 在每次调用持有者期间用独立数据库连接持锁，仍保持原生 RPC 位于 Spring 事务之外。控制台可为尚无租户链行的历史链创建 `CLOSED` 且暂停的记录，暂停事务持同一咨询锁，故不会在暂停提交后首次广播旧字节。平台当前停用的链仍显示在 Console，可紧急暂停，但不可从该行开链或恢复提现。既有链上结果继续对账；这两类链的多热钱包库存、路由和完整救援仍未接入。
- 已完成四方隔离的旧钱包可在 Console 只读查看配置资产的链上库存，包含本地该网络登记后已停用、且已从 `chain_asset` 路由投影移除的历史 EVM 代币；另一个网络复用相同币种符号不算此钱包资产。独立审批侧仍须保留相同网络和资产的登记，用原已登记公钥推导地址，通过独立 RPC 查询余额，并返回原隔离事件指纹；缺少独立登记时盘点失败，不静默略过该资产。Wallet 逐项核对租户、原 key、链、网络、地址、隔离事件、币种、本地精度、原生精度、非负金额及观察时效；EVM 代币还要与本地该网络的合约地址和精度一致，并在 Console 显示合约地址。不写客户账本或恢复签名权限。页面明确提示未知代币和尚未登记的历史合约仍未覆盖，不能把列表当成“全部资产已找到”。
- 热钱包登记后，数据库禁止删除或改写该链、该网络现有 `token_config` 的符号、标准、合约地址及精度等身份字段；可停用原配置或调整非身份运行参数。登记热钱包自身的租户、地址、key、链、网络身份及其引用的托管地址身份也不能被改写或删除；已隔离或退役状态不能回退，隔离事件和四方确认时间一经写入不得改写。并发登记和配置修改共用事务锁，避免两边均看不到对方尚未提交的记录。新部署使用初始化 SQL；存量库先执行 `scripts/ops/upgrade-hot-wallet-token-identity-guard.sql`，再依赖此防线。升级前已经覆盖或删除的旧合约无法由触发器还原，必须从配置备份、审计和独立审批登记中逐项追溯。
- 对 EVM 旧地址，独立审批侧在余额观察的同一块高读取 `eth_getCode`，识别空代码、EIP-7702 委托标记及异常代码，复读区块哈希以拒绝观察期间的重组。Console 显示委托目标和观察区块；这只是当前链上状态证据，不能撤销委托，也不能证明此前签发的授权或交易已经失效。
- 正常 EVM 热钱包库存及已确认直接支出的独立余额核对也读取同块原地址代码。空代码可用；若已委托，只接受独立审批配置中该租户预装的归集或提现 delegate，并核对该 delegate 在同块的实际代码哈希。未知委托或其他可执行代码使库存证明失败，阻止继续把该地址分配给新归集或新提现。这是使用前检测，不替代链上撤权。
- 活跃地址的库存证据由后台分页刷新；单个地址或资产失败时继续扫描其余地址。一次独立刷新失败就按原观察时间条件标记该资产库存失效，立即阻止新归集和新提现；已签交易在首次广播或未知结果重广播前也锁住并检查原热钱包的全部库存标记，失效时拒绝发送。并发的新有效观察不会被较早的失败覆盖，后续成功刷新可清除标记。60 秒过期也拒绝新路由。观察仍是采样，不能保证在两次查询之间立刻发现链上变化；独立签名权限和应急暂停仍须各自生效。

## 完成应急自动切换前必须闭合的资金边界

1. **资产分仓。** 每租户、每链、每资产只向多个 `ACTIVE` 热提地址补到目标余额，严格限制单钱包和全租户热资产暴露。超过最高余额立即停止自动补资和该钱包路由；冷储备使用不同审批人员、设备与网络。
2. **在途预留。** 已有新提现与归集的原子占额仍需扩展到 Gas、EIP-7702 批次及其他链的规范锚点释放。`BROADCAST_UNKNOWN`、已签名和链上未终结交易不能释放占用；当前普通 EVM 单笔提现和直接归集有 finalized 证明释放路径，其他链与 7702 批次仍可能因保守占额停止新路由。
3. **原子切换。** 先暂停新提现及补资，核对备用钱包 key、逐资产独立规则、新鲜库存、链上委托/allowance 与全部在途订单；再一次提交新归集目标和新订单出款路由。旧订单保持原来源，不能静默改绑。新路由启动前完成独立审批与原生持有者检查。
4. **资产转移。** 从可能泄露的 key 向预装且独立批准的安全目的地址发起逐资产、逐链的应急转移，含原生币、Token、UTXO 和 Gas。每笔使用预设限额、唯一幂等编号、人工双人批准、独立签名凭据和链上确认；不可把“点击切换”视为全部资产已转移。
5. **链上授权撤销。** EIP-7702 委托、合约 allowance、待确认 nonce 和已签交易必须单列清单、按链处理和复核。单靠本地隔离无法撤销已经广播或链上生效的权利。

上述第 2–5 步尚未形成可用的应急自动闭环；当前 Console 提供准备、预检、库存观察、单钱包启用、暂停、隔离和分阶段应急路由切换。切换只影响新账户链业务与旧 key 的本地/独立签名权限，不是资产转移完成凭据。

当前隔离会永久禁止原 MPC key 在原生持有者和独立审批域获取新签名。因此不能在隔离后假设原 key 仍能签署救援转账；必须先按链设计独立且预装的恢复权限、受限救援签名路径或其他链上可执行的迁移机制，并验证其在密钥全泄露及部分持有者失陷两种情形下的竞争与授权边界。若攻击者已取得完整私钥，任何本地暂停或 MPC 隔离都无法撤销其链上签名能力，只能争取先转移资产并撤销可撤销的链上授权。

EVM 已增加独立的 `Eip7702PayoutRecoveryDelegate` 合约及本地链测试，作为**未来预装**的救援权限基础。它继承原批量提币接口，每个部署实例把安全收款地址和三名互异应急审核员固化在字节码中；任意两名审核员对旧 EOA、chainId、资产、精确全额、递增 nonce 和截止时间共同签名后，任何中继者可将该资产完整转到固定安全地址。首次成功救援会把继承的提币 nonce 冻结在最大值，阻止该委托下的旧批量提币签名继续执行。错误金额、税费代币、重复签名、单人签名与重放会回滚。该合约目前**没有部署、预授权或接入 Wallet/Approval 救援状态机**，现有钱包仍无独立救援权限，事故清单返回 `NO_INDEPENDENT_RECOVERY_AUTHORITY`。当前 `evm_7702_config` 按链和网络共用一个提币委托地址，生产接入前还必须改成逐热钱包委托地址与代码哈希绑定，才能使用不同租户的固定安全地址。救援权限必须在事故前安装；完整私钥泄露者仍可重新委托其他代码或直接转账，因此两人授权也不能保证抢先转移。生产接入还需要独立审核员密钥保管、逐租户部署与代码哈希校验、链上授权核对、幂等广播、逐资产终局对账和撤销旧委托的操作流程。

## 操作顺序

发现可疑签名或余额异常时，先暂停受影响租户/链的新提现和补资，保全原始审计与 RPC 证据；隔离可疑 key 并确认三个原生持有者和独立审批回执；检查其他租户、链和服务身份是否共用入侵路径；撤销被盗部署凭据、证书和工作站访问。随后逐链核对待确认交易、EIP-7702 委托和 Token 授权，执行经独立审批的转移与撤销，等待链上终局并完成客户账本/链上资产对账后分阶段恢复。

疑似旧热钱包密钥泄露时优先使用应急切换入口，它会同事务提交提现暂停与旧钱包本地隔离。单独点击“隔离热钱包”也会在同一事务先暂停该链，再隔离原 key；即使独立回执暂时失败，本地暂停和隔离仍已提交。单独点击“暂停提现”不会把仍为 `ACTIVE` 的热钱包从归集目标中移除；若备用钱包尚未准备好，也应立即隔离旧钱包并保持暂停，不能等待资产盘点结束后才隔离。
